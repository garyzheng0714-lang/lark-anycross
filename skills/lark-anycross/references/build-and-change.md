# 搭建与修改

组件的事件、动作和参数查 [资料库](guide/README.md)。拖拽、胶囊、调试的界面步骤查 [Computer Use 手册](guide/guides/COMPUTER_USE.md) 和 [浏览器操作控制台](browser-automation.md)。组合套路（分页、卡片、Webhook）查 [搭配配方](guide/guides/RECIPES.md)。

## 动手前

1. 确认用户点名的项目 ID 和工作流 ID，核对页面左上角的当前项目。
2. 有风险的改动先给用户看清楚：改哪几处、每处改前改后的样子、怎么验证、怎么回退。一张单页 HTML 图就够。用户点头后再动。
3. 先在界面导出当前工作流，存进 `~/.anycross-backups/`，用脚本读成大纲，弄懂整条流程再动。再记下线上版本号，回滚靠它。这条工作流在 [workflows/](workflows/README.md) 里有档案的，拿新导出和档案对一遍，对不上以新导出为准。见 [导出与读懂](export.md)。（实测）
4. 比较草稿和线上版本。草稿可能积着很久没发布的改动，发布会把它们一起带上线。把差异列给用户看。（草稿积压是实测）
5. 中途发现计划要变（比如下游服务早就下线了），停下来报告，等用户同意。

## 备注怎么写

目标是让没学过代码的同事打开流程就看懂：它做什么、什么时候跑、动了哪些数据、出事找谁。搭完和改完都要把下面几处写好，写不清楚就不算搭完。

| 位置 | 怎么写 | 例子 |
|---|---|---|
| 工作流名称 | 「做什么 \| 怎么触发」 | `定时对账 \| 每 2 小时`、`通知各项目 \| 名单变了` |
| 工作流描述（点名称旁的笔，最多 300 字） | 用大白话写四件事：为什么有这条流程、什么时候跑、读写了哪些表或系统、出问题会怎样，以及负责人 | 「每 2 小时把飞书停用名单和各项目对一遍，防止漏掉离职的人。只读名单、写入数据存储里的『最新停用名单』。停跑的后果是离职的人最长还能登录 2 小时。负责人：张三。」 |
| 每个节点的显示名称 | 写这一步在业务上做了什么，不写组件名 | `数据存储` 改成 `把最新停用名单存起来`；`HTTP 请求` 改成 `通知各项目来拉名单`；`手动触发器` 改成 `管理员手动紧急下线` |
| 分支的每条路径 | 写条件的业务含义 | `名单有变化`、`名单没变，结束` |
| 项目配置、数据存储的键 | 名称看得出用途，描述里写谁在读写 | `接入项目通知地址`，不要叫 `config1` |
| 代码节点 | 显示名称写它算出了什么，脚本开头一行中文说明输入和输出 | `算出这次新增的停用人员` |

- 默认名一律改掉。画布上看到「数据存储」「HTTP 请求」「循环」「分支」「手动触发器」这种组件原名，就说明还没写完。
- 节点的实例 ID（如 `http-client-3`）改不了，也不用改。表达式照常用 ID 引用，显示名称给人看。
- 改了流程的行为，同一次把名称和描述一起改掉，别让描述和实际对不上。
- 交付前打开流程从上往下读一遍，只看名称和描述就能讲清楚这条流程，才算写好。

## 整理项目和分类

- 工作流不能移到别的项目。菜单只有「移动到文件夹」（本项目内）和「创建副本」（可选别的项目）。（实测界面，官方文档同，2026-11）
- 跨项目副本是新工作流：网址触发器回调地址是新的，要重新发布，运行日志不跟过去，原调用方全得改地址。（实测，比对地址指纹）
- 不是网址触发的也不一定能直接搬。搬之前逐条查：（2026-11-12 盘 235 条时整理）
  - 项目配置不跟副本过去，副本里的 `$.config.<配置名>` 在目标项目取不到，要重建，密钥由用户本人填。（实测）
  - 数据集合属于项目，存的数据带不过去。（文档加推断）
  - 子流程、告警按工作流 ID 互相指，副本是新 ID，要改指向。（实测）
  - 副本取的是草稿，不是线上版本，草稿里没上线的改动会跟着上线。（实测）
  - 副本没发布、没启用，运行记录不跟过去。定时任务先启用副本再马上停原件，免得跑两遍。（前半实测，后半推断）
  - 审批、企业微信事件触发的副本能不能收到事件，没验证。
  - 凭证不分项目，副本里凭证 ID 和原件一样；副本实际跑能不能用上，没验证。（接口实测）
- 所以整理只在项目内做：改项目名、建文件夹、纯副本项目导出后删。有用户明确否掉过靠副本跨项目搬。
- 分项目：一个部门或一项共用服务一个项目，项目里用文件夹分事情，不建一个大项目按部门分文件夹。权限和数据按项目隔离、分享只能按项目给（官方文档），项目配置整个项目共用、「加密文本」是明文（实测）。文件夹能不能嵌套没验证。
- 项目内挪进文件夹不影响流程：工作流 ID、回调地址指纹、发布和启用状态挪前挪后都一样。（实测，2026-11，挪 73 条后逐条回读）
- 批量整理用页面自己的写接口，请求头带 `x-csrf-token`，值取 cookie `anycross_csrf_token`。（实测，2026-11）
  - 建文件夹：`POST /webapi/projects/<项目ID>/folders`，`{parentFileID: <文件树根节点 id>, name}`。同项目文件夹不能重名（`code 9`）。
  - 挪进文件夹：`POST /webapi/projects/<项目ID>/files/batch_move`，`{fileIDs, referenceFileID: <文件夹 id>, position: 2}`。`fileIDs` 是文件树节点的 `id`，不是工作流 ID。
  - 改项目名：`PATCH /webapi/projects/<项目ID>`，`{name, desc, icon}` 一起交。先 `POST /webapi/project/<项目ID>`（体 `{}`）读出原 `desc`、`icon` 原样带上。批量改时，刚打开的页面会自己跳转，读请求可能拿到空 `data`；每步带重试，按「现名是新名就跳过、是旧名才改」写，断了能整段重跑。改完用项目列表接口整体回读。（实测，2026-11-12 改 18 个）
  - 项目命名按服务的业务分（`业务｜服务`），别按触发方式或形式（回调、卡片）分：同一件事常同时用定时、网址、手动几种触发，项目配置、数据存储、子流程又只在本项目内能共用。按形式建的项目最容易混进别的业务的流程。（2026-11 盘点所见）
  - 删项目：界面「当前项目」右边「···」→「删除」，输入项目名确认；接口是 `DELETE /webapi/projects/<项目ID>`，体 `{}`。项目配置和数据存储跟着一起没，删前看它们和工作流是不是都空。确认框晚一两秒才出来，截图可能拍不到；删完页面会跳到别的项目。删后读详情返回 `40001`。（实测，2026-11）
- 动手前按盘点方法重查状态，别直接用旧名单；做完回读文件树核对条数，再逐条比发布和启用状态。（实测）
- 把真没用的流程收进备份项目：先导出 zip 存本机，再跨项目复制、比对、删原件。（实测，2026-11）
  - 导出：`GET /webapi/projects/-/flows/<工作流ID>/export?name=<名称>`。脚本连续下载会被 Chrome 拦，多份合成一个文件，新开一个同源标签页只下载一次。
  - 复制：`POST /webapi/projects/<原项目ID>/flows/<工作流ID>/duplicate`，`{name, targetProject}`，返回新 `flowID`。副本是草稿。每步 `operation` 只剩组件 ID 和动作 ID，触发器换了新的回调地址或 `hookKey`。比对时排除这几处。
  - 删除：`DELETE /webapi/projects/<项目ID>/flows/<工作流ID>`，体 `{}`。删了无法恢复。
  - 批量删：删前逐条核原件在、名字对、40 天 0 次运行、副本在备份文件夹里；每条删前再查一次运行次数。删完回读文件树核对。一次删几十条可能被 Claude Code 安全检查拦下，先把逐条清单给用户确认。（实测，2026-11）

## 改动的固定循环

每改一处都走一遍，验证通过再改下一处。（实测）

1. **备份。** 导出一份，记下线上版本号。
2. **查引用。** 看大纲末尾「谁用了谁的输出」，确认没有下游步骤用到要删或要改的那步。
3. **改。** 在草稿上改。
4. **回读比对。** 用只读接口读回来，和备份比，确认只改了想改的地方。
5. **真跑一次。** 用测试数据跑，看业务结果有没有出现。
6. **看日志。** 每一步都成功，再看下游返回的内容。
7. **收尾。** 发布后再导出一份，和改前的导出比一次差异，确认线上只多了想改的地方。有档案的同步改档案。

回滚就是切回第 1 步记下的线上版本号。轮换密钥放到所有改动都验证完之后，因为旧密钥一作废就回不来。

## 保存、发布和生效

- 集成平台：「完成」只是退出编辑，不等于发布。状态显示「未运行 / 有更新未发布」时，调试其实已经跑过。（实测）
- 调试运行和已发布的流程共用同一份数据存储。调试会写到正式数据。（实测）
- 并行循环的各圈共用流程变量。拿流程变量控制「每条记录写失败就重试」，会有记录一次也没写上，节点却全是成功。实测每轮漏写约 13%。要重试就用节点自己的出错重试，或者改成串行循环。（现象实测，原因推断，2026-11-12；详见 [画布](guide/guides/COMPUTER_USE.md)）
- 项目配置在发布那一刻冻结进版本：改了项目配置，已发布的工作流照用发布时的值，要重新发布才生效。编辑框那句「修改项目配置后，被未发布的工作流引用的配置也将同步修改」说的就是这个。查法：`GET /webapi/flows/<工作流ID>/versions/<版本ID>` 的 `referencedVariables` 是发布时的值，再对一次运行日志的节点入参。例：一条流程的「通知地址」配置发布后陆续加了 8 个地址，半个月后的运行仍只发了发布时那 1 个。草稿和线上一样时，重新发布只刷新这份值；发布弹窗要选配置组，配置组里没填的项用默认值。子流程调用方只记子流程 ID 不记版本，子流程重新发布后调用方不用动（推断）。（实测，2026-11-12）
- 数组类项目配置删一项：编辑框里元素左边的垃圾桶点了，确认气泡不出来（DOM 里有，visibility 是 hidden）。直接把那一项改写成要的值。（实测，2026-11-12）
- 退出调试时弹「当前调试结果未保存」。要留证据就点「保存本条记录」，未保存的平台不留。含手机号这类个人信息的调试结果就不要存。（实测）
- 多维表格自动化：没点「保存并启用」就不生效。离开时弹「放弃修改工作流？内容尚未发布」，说明没上线。（实测）
- 用 `lark-cli base +workflow-update` 改多维表格自动化是整份替换，平台会顺手改掉几处。改完一定 `+workflow-get` 读回，和改前逐项比。（实测，2026-11-12）
  - 「修改记录时」触发器读出来没有 `trigger_control_list`，意思是批量操作不触发。整份发回去时不带这一项，平台会补成 `pasteUpdate`、`automationBatchUpdate`、`appendImport`、`openAPIBatchUpdate` 四种都触发，行为就变了。要保持原样，显式传 `[]`，读回来又是没有这一项。
  - HTTP 步骤里界面留下的空请求头（`key` 是空的）会被拒，报 `800004006 headers[0].key must be non-empty string`。删掉这一行就行，它本来就不发。
  - GET 请求的 `body_type` 会被改成 `none`（原来是 `raw` 加 `{}`）。被调的流程只读网址参数就没影响，读请求体的要先查。
  - `--json @文件` 只认当前目录、`/tmp` 和 `~/files` 下的文件，`-`、`@-` 都不行。文件在别处就写 `--json "$(cat 文件)"`。
- 发布、停用、启用工作流的页面接口，和停用后网址回 404 的现象，见 [用页面接口写整条草稿](guide/guides/COMPUTER_USE.md#13-不点画布用页面接口写整条草稿)。换下一条还在跑的接力链的顺序见 [搭配配方](guide/guides/RECIPES.md) 第 4 节「换下老链」。（实测，2026-11-12）
- 用接口改流程描述，先数字数，别超过 300 字。接口不拦，超了也存得进去，之后这条流程改名、改描述、存草稿、调试、发布全被拒（`flow desc too long`），没有办法解开，连删除、导出也被拒，只能新建一条重搭，旧的挪进闲置文件夹。重搭要换的地方见 [用页面接口写整条草稿](guide/guides/COMPUTER_USE.md#13-不点画布用页面接口写整条草稿)。（实测，2026-11-13）
- 删一个步骤：鼠标移到步骤上会出现删除图标。（实测）
- 节点多、脚本长时，不用一个个点画布：在本机生成整条定义，用页面接口写进草稿。写法和各种节点的格式见 [用页面接口写整条草稿](guide/guides/COMPUTER_USE.md#13-不点画布用页面接口写整条草稿)。（实测）
  - 新建流程也能走接口，直接建进文件夹；网址触发器要另外补回调地址，否则校验报 `errorEmptyWebhookURL`；分支条件每项不包 `{type, value}`，操作符名校验不查、写错了要到点「调试」才报 3412，「不为空」是 `notEmpty`，它把空字符串、空数组也算不为空；节点描述别超过 60 来字。细节同一节。（实测，2026-11-12）
  - 「异步调用子流程」「子流程触发器」「错误处理设成忽略」的写法同一节。被调用的流程有校验错误时，调用方报 `errorSubFlowError`。（实测，2026-11-12）
  - 运行时三条要记住：分支和出错分支里的节点，在分支外面引用不到（拿到空），要带出来就改流程变量；被「忽略」或「走分支」接住的错误不算运行失败，要让告警接到就让节点报错并设成「终止」；并行循环里别用流程变量当 While 条件或存每项的中间结果，几路共用一份会漏写、重写；变量节点的步骤 ID 必须是 `variable-数字`，否则运行时报 `unsupported node type`；走到「结束」节点整次运行算成功，不触发告警。细节同一节。（实测，2026-11-12）
  - 「无限触发（接力链）+ 水位线增量 + 分棒全量 + 断了自动拉起」和「连续失败 3 次才告警」两个现成做法见 [配方](guide/guides/RECIPES.md)。要常年跑的，照配方里那几条加固：被顶替的旧棒自己停（和接力记录比谁新，不只对号；读不到照常跑但不改记录；认不出的接力号当最旧的，拉起时带的怪号换成现在的毫秒数）、一棒限时（超过 3 小时主动报错）、限流按错误码数字认而不当坏数据、读不到就别乱提醒、消息回了 `message_id` 才记「提醒过」、看门自己也要有心跳。（搭好并校验，未实跑）
  - 节点出错时下游拿到什么、数据存储读不到时拿到什么、批量新增遇错是不是整批不写，先看 [实测行为](guide/guides/VERSIONS_AND_LIMITS.md#6-实测行为)。数据存储「获取值」的默认值别设成空，设成 `{}`、「无」这类读失败不会出现的值，才分得清「从没记过」和「这次没读到」。（实测，2026-11-12）

## 自己建连接器（含批量建操作）

第三方系统没有现成组件，或现成组件动作太少时，自己建。完整做法见 [自建连接器实操](guide/guides/CONNECTOR_DEVKIT.md)，要点：

- 第三方接口用固定令牌的，新建时服务选「平台预置」里的 **HTTP Bearer Token**，不用写认证插件。（实测）
- **连接器是通用工具，密钥是变量**：连接器里不存任何人的密钥，谁用谁在凭证里填自己的，调到的是他自己的账号。所以封装个人账号类的服务也能给同事共用。别把它想成「绑着某人账号、不能给别人用」。要给同事用，在「用户与渠道 → 可用范围」里加人。（实测）
- 操作多就别在界面里一个个点：在已登录的控制台页面里调 `POST /webapi/v3/connector_drafts/<草稿ID>/actions` 批量建，58 个操作一分钟建完。请求体格式、表单定义写法都在上面那份文档里。（实测）
- 界面按样例生成的入参，会把请求体每个顶层键都变成入参；要写死常量得走接口建。（实测）
- 改一个操作走 `PUT`，要把读到的整个操作对象改完原样发回去；别删了重建，那样会换 ID，已经在用的流程会断。（实测）
- 必填项是字段上的一条校验规则 `formConfig.validations: [{"type": "required"}]`，界面上没有开关。（实测）
- 发布后的小改动选「在当前版本中发布更新」，使用者自动生效。（实测）
- 表单字段的 `formPath` 写错，参数会悄悄丢掉、不报错：它去掉 `$.body.` 后必须等于模板里 `input` 下的路径。建完一定用调试台看一眼「HTTP 日志」里真正发出去的请求体。（实测）
- 批量试跑调 `…/actions/<操作ID>/test`，不用一个个点调试台。（实测）
- 把大段定义送进页面：页面访问本机 127.0.0.1 会卡死，用「临时 file input + 上传文件工具」。（实测）
- MCP 服务如果不握手也能直接 `tools/call`，就能一个工具封成一个操作。（对滴答官方 MCP 实测）
- 对方要先用账号密码换令牌：认证选「客户端凭证（OAuth2ClientCredentials）」，认证表单加一个 `baseURL` 下拉放正式、测试两个地址，使用者选哪个，所有操作的 `{{baseURL}}` 就跟着换。测试认证时「获取」「刷新」两个页签都要把「认证流程」和「业务接口」各测一遍，否则发布时报「测试风险」；发布后还要回「认证与授权」勾上它。（实测）
- 对方网关按 `User-Agent` 放行时，平台发出的请求会被拦（推断它换掉了自定义 UA），再加一个对方认可的 `Referer` 才过。认证测试只显示「50 未知错误」时，读 `…/connections/<key>/observed_data` 看真实返回。（实测）
- 查询参数、请求头参数：`formPath` 写 `$.queryParams.名` / `$.headers.名`，模板仍写 `{{input.名}}`。对方「HTTP 200 + 业务码」的，状态码配 `{{body.code}}` 等于 0，失败时会带出对方原话。（实测）
- 试跑接口的入参每个值都要包一层，写成 `{"名": {"value": 值}}` 就行，平铺写会报 `unmarshal from paramJSON failed`；认证测试数据的 key 可以直接当 `authKey`。（实测）

## 拿飞书 token：用自建连接器

HTTP 节点的凭证只支持 Basic、API Key、Bearer，换不了飞书 token。项目变量没有加密类型。所以别在流程里写 `app_secret`。（实测）

做法：建一个自建连接器，认证选「飞书应用身份认证」，平台会自己注入 `tenant_access_token`。（实测）

- Base URL 填 `https://open.feishu.cn/open-apis`。URL 里写 `{参数}` 占位，会自动变成输入项。
- 每个操作必须选「所属分组」。
- 发布后只对开发者自己可见。渠道只有「飞书集成平台」和「飞书 aPaaS」，多维表格自动化的步骤菜单里用不了它。
- 飞书原生连接器不支持「关联组织」接口。要调关联组织的接口，只能走自建连接器。（实测，174 个连接器逐个看过）

## 凭证

- 凭证存的是密钥的一份副本。按数据结构看，轮换密钥后它不会自动跟着更新。（存副本是实测，不自动更新是推断）
- 「选择飞书应用获取凭证」只列出本租户的应用，不用手敲密钥，优先用它。其他租户的应用只能「输入凭证」，由用户本人填。
- 凭证下拉里有重名。按事先记下的凭证 ID 对上再选，选中后显示「新版 xxx · 已连接」。
- 凭证也可以不点画布、直接用接口选。凭证 ID 从凭证列表接口取，写进节点的 `auth.credentials: {type: "cred", value: <凭证 ID>}`，再写回草稿。整个过程不碰账号密码。写法见 [不点画布写草稿](guide/guides/COMPUTER_USE.md)。（实测，2026-11-12）

## 代码节点

- 动态脚本写 `function handler(input)`，只能用 JS，限时 1 秒，不能联网，不能装 npm 包，时间按 UTC。（文档；一次实测 46 毫秒跑通）
- 脚本输出在选择器里只能选到 `result`，选不到更深的字段，见 [表达式模式](browser-automation.md#表达式和胶囊)。
- 表达式、动态脚本、Workflow Skill 代码节点、连接器开发 SDK 是四种不同环境，语法不能混用。见 [代码与导出](guide/guides/CODE_AND_EXPORT.md)。

## HTTP 节点

- 对方返回的不一定是 JSON 时，把响应解析设成 None，否则节点报错。
- 通知类调用的错误处理设成「重试，然后忽略」，别让一个下游拖垮整条流程。
- 单次最长 60 秒。并行循环 maxSize 最大 10。（文档）
