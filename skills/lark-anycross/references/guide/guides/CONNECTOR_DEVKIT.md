# 自建连接器：界面流程、背后的接口与批量建操作

2026-11-11 在一个真实租户里从零建了一个 58 个操作的自建连接器（把一个第三方 MCP 服务封装成连接器）。下面每条都标了证据等级：**实测**是真做过并看到了结果，**未验证**是配了但还没跑过。

官方的概念说明见 [代码与导出 §3](CODE_AND_EXPORT.md#3-自建连接器的构成)。本页只记实际操作时才会知道的东西。

## 1. 界面流程（实测）

入口：控制台左侧「连接器」→ 顶部连接器下拉 →「新建连接器」。

1. **选要集成的服务。**「平台预置」里有四个通用 HTTP 服务，区别只在认证：HTTP Basic、HTTP No Auth、HTTP API Key、HTTP Bearer Token。第三方接口用固定令牌的，选 HTTP Bearer Token，平台会把凭证里的值放进 `Authorization: Bearer …`，不用自己写请求前插件。
2. **填基础信息。**名称不超过 30 字；标识符 12–30 位，只能小写字母、数字、下划线，字母开头；说明不超过 100 字。
3. 建好后在「基础信息」里配 Base URL，在「认证与授权」里点「编辑」勾上认证。这两处没配，左侧菜单会有红点。
4. **新建操作分两步。**
   - 基本信息：操作名称（≤30 字）、操作标识符（5–60 位）、说明（≤100 字）、用途（建后不可改）、所属分组（必选，下拉里可以当场新建）。
   - API 信息：请求方式、相对路径、请求头、请求体样例、响应体样例。
5. 「状态码配置」里可以填应用状态码路径和错误描述路径，再在「状态码表」的成功条件里加一条「应用状态码 等于 某值」。

踩到的坑：

- **保存时平台按样例自动生成入参**：请求体样例的每个顶层键都会变成一个入参，模板写成 `{{input.键名}}`。想让某些键是写死的常量（比如 JSON-RPC 的 `jsonrpc`、`method`），只能事后改 API 映射，或者直接走下面的接口建。
- 新建操作的弹窗里按 Esc 会弹「确定退出编辑吗？」，下拉没收起时别用 Esc。
- 请求体、响应体的编辑器是 CodeMirror 6，不是 Monaco。写入：`el.querySelector('.cm-content').cmView.view.dispatch({changes: {from: 0, to: 原长度, insert: 文本}})`。
- URL 里的 `connector-v2/<数字>` 是**连接器 ID**；操作、分组这些接口用的是**草稿 ID**，两个不一样。草稿 ID 从页面请求里看（`connector_drafts/<草稿ID>/actions`）。

## 2. 背后的接口（实测）

都在已登录的控制台页面里用 `fetch` 调，带 `credentials: 'include'`。写接口要带请求头 `x-csrf-token`，值是 cookie `anycross_csrf_token`。

| 做什么 | 接口 |
|---|---|
| 读连接器草稿 | `GET /webapi/v3/connector_drafts/<连接器ID>` |
| 读全部分组和操作 | `GET /webapi/v3/connector_drafts/<草稿ID>/actions` |
| 新建分组 | `POST /webapi/v3/connector_drafts/<草稿ID>/groups` |
| 新建操作 | `POST /webapi/v3/connector_drafts/<草稿ID>/actions` |
| 更新操作 | `PUT /webapi/v3/connector_drafts/<草稿ID>/actions/<操作ID>` |
| 删除操作 | `DELETE /webapi/v3/connector_drafts/<草稿ID>/actions/<操作ID>` |
| 调试一个操作 | `POST /webapi/v3/connector_drafts/<草稿ID>/actions/<操作ID>/test` |

新建分组的请求体：

```json
{"name": {"i18nKey": "<随机 uuid>"}, "groupWhat": "actions",
 "i18n": {"<同一个 uuid>": {"zh-CN": "分组名", "en-US": ""}}}
```

新建操作的请求体：

```json
{
  "internalSettings": {"onPropertyInExprAbsent": "not_include_field"},
  "groupID": "<分组 ID>",
  "name": {"i18nKey": "<uuid 甲>"},
  "description": {"i18nKey": "<uuid 乙>"},
  "alias": "操作标识符",
  "purpose": "public",
  "inputPresent": "<字符串化的表单定义，见 §3>",
  "outputPresent": "<字符串化的出参定义，见 §3>",
  "inputSchema": "<字符串化的 JSON Schema>",
  "outputSchema": "<字符串化的 JSON Schema>",
  "apiCall": {"reqTemplate": {
    "url": "{{baseURL}}/相对路径", "method": "post",
    "headers": {}, "queryParams": {},
    "body": {"写死的键": "常量", "来自入参的键": "{{input.字段名}}"},
    "bodyType": "RawJSON"}},
  "i18n": {"<uuid 甲>": {"zh-CN": "操作名", "en-US": ""},
           "<uuid 乙>": {"zh-CN": "操作说明", "en-US": ""}}
}
```

- 请求体模板里**常量和 `{{input.x}}` 可以混写**，嵌套对象里也行。整个值就是一个模板时，对象、数组、数字会按原类型代入。
- `onPropertyInExprAbsent: "not_include_field"` 的意思是：入参没填，这个字段整个不发。可选参数多的接口靠它。
- **更新要把整个操作对象发回去。**先 `GET …/actions` 拿到这个操作的完整对象（带 `id`、`key`、`connectorDraftID`、`seqNum`、`createdAt` 等），改掉要改的字段，再补一个 `"referredByThis": []`，整体 `PUT` 回去。只发新建时那几个字段会返回「参数无效」（10000006）。更新不换操作 ID，已经在用它的流程不受影响；删了重建会换 ID，所以连接器发布后要改操作一律走更新。
- 一次建 56 个操作，每个间隔 0.25 秒，全部成功，没碰到限流。
- 地址写 `{{baseURL}}/相对路径`，别写完整地址。写完整地址时请求本身是对的，但界面会显示成「基础路径 + 完整地址」，有人在界面上点「编辑」保存一次就会被拼坏。（实测）
- `GET` 操作的 `reqTemplate` 不带 `body` 和 `bodyType` 就行，请求体发出去是空的。（实测）
- 平台默认的状态码表就够用：对方回 401 时显示「认证失败」，对方返回里的报错文字会自动带出来。（实测）

## 3. 表单定义的写法（实测）

`inputPresent` 最外层：`{"spec": "1.3", "type": "object", "bindingType": "formItem", "properties": {…}}`。每个字段一个节点：

```json
{"type": "string", "bindingType": "formItem", "name": "字段名",
 "formPath": "$.body.路径.字段名",
 "formConfig": {"type": "input", "label": "显示名", "tooltip": "提示",
                "showType": {"string": "input"}}}
```

| 字段类型 | `formConfig.type` | 另外要带 |
|---|---|---|
| string | `input` | |
| number | `inputNumber` | |
| boolean | `switch` | |
| object | `form` | `properties` |
| array | `dynamicList` | `items` |

**`formPath` 决定模板里的 `input` 长什么样，写错了参数会悄悄丢掉。**`formPath` 去掉开头的 `$.body.` 后，就是这个字段在 `input` 下的路径。所以模板里写 `{{input.project_id}}`，对应字段的 `formPath` 必须是 `$.body.project_id`，哪怕它在请求体里的真实位置是 `params.arguments.project_id`。按真实位置写成 `$.body.params.arguments.project_id` 的话，表单能显示、能填，但发出去的请求里这个参数是空的，也不报错。（实测：改之前参数为空，改之后正常）

数组有两处怪写法，照抄界面自己生成的才能正常显示：

- 数组节点的 `formPath` 是 `$.body.<字段名>[*]`，不带上级路径。
- `items` 节点的 `name` 固定写 `array[index]`，没有 `formPath`；元素是对象时，它的子字段 `formPath` 写 `$.body.<数组字段名>.<子字段名>`。

`outputPresent` 的节点更简单：`{type, bindingType, name, formPath, title}`，对象带 `properties`，数组带 `items`，数组的写法同上。出参定义得越细，工作流里能直接点选的字段就越多。

出参只声明成 `{type: object}`、没列子字段，运行时子字段照样完整传下去，下游用表达式 `$.节点.data.records[0].某子字段` 能取到（实测，2026-11-12：持票人的「表单内容」两层嵌套对象，节点日志里子字段齐全）。没声明的子字段只是不能在选择器里点选，要手写表达式。

**必填**不在 `inputSchema.required` 里生效，界面上也没有单独的开关。它是字段节点上的一条校验规则：

```json
"formConfig": {"type": "input", "label": "…", "tooltip": "…", "showType": {"string": "input"},
               "validations": [{"type": "required"}]}
```

加上以后，入参表的「是否必填」变成「是」，使用者没填时表单直接提示「该字段为必填项」，「调试」按钮也点不了。`tooltip` 就是字段旁小图标上的提示，支持 Markdown，把「这一格该填什么、可选值有哪些」写在这里。

## 4. 把一个 MCP 服务封装成连接器（实测）

有些 MCP 服务器可以当普通接口调：不握手，直接发一次 `POST`，请求体是 JSON-RPC 的 `tools/call`，返回 `application/json`。先用 curl 确认它不握手也回结果，再往下做。

- 一个工具对应一个操作。请求体模板把 `jsonrpc`、`id`、`method`、`params.name` 写死，`params.arguments` 里每个参数写成 `{{input.参数名}}`。
- 工具清单（`tools/list`）里自带每个工具的入参和出参 JSON Schema，可以写脚本直接转成 §3 的表单定义，不用手敲。转的时候要先把 `$ref` 展开、把 `anyOf [X, null]` 取成 X。
- 每个操作的请求头要带 `Accept: application/json, text/event-stream`。不带的话服务器回「Not Acceptable: Client must accept application/json」。平台默认只带 Content-Type。（实测）
- 工具报错时 HTTP 仍是 200，错误在 `result.isError`。所以状态码要配：应用状态码路径 `{{body.result.isError}}`，成功条件加「应用状态码 等于 false」。实测有效：工具报错时调试台显示「调试失败」，并把错误文字带出来。

## 5. 往控制台页面里送大段数据（实测）

批量建操作要把几百 KB 的定义送进页面。

- 页面里 `fetch('http://127.0.0.1:…')` 走不通：请求一直挂着不返回，连带 JS 调用 45 秒超时。应该是浏览器的本地网络访问限制，别在这上面耗。
- 可行的办法：在页面里临时加一个 `<input type="file">`，用浏览器扩展的「上传文件」工具把本机文件塞给它，页面里 `await input.files[0].text()` 读出来。数据不经过网络。
- 页面刷新后 `window` 上的东西全丢，要重新上传。

读页面数据时：

- 一次 JS 调用的返回大约 1000 字就被截断，大对象要挑字段分几次读。
- 返回内容长得像 cookie 或查询串（`a=1; b=2`、带参数的 URL）会被整个拦掉。返回 JSON，别自己拼 `键=>值` 这种串。
- 想知道某个按钮背后发了什么：在页面里包一层 `fetch` 和 `XMLHttpRequest`，把非 GET 请求的地址和请求体记到 `window` 上，再去点按钮。

## 6. 连接器是通用工具，密钥是每个人自己填的变量

连接器默认就是给全公司用的，以后还可能给外部的人用。别把它当成「绑着某个人账号的东西」，名称、说明、帮助文档都不要写成某个人专属。它只定义怎么调接口；账号是谁的，由使用的人在凭证里填。

- 「认证与授权」里选的认证方式（比如 HTTP Bearer Token），就是在声明「用这个连接器要填一个什么样的密钥」。连接器本身不存任何人的密钥。（实测）
- 每个使用者建自己的凭证、填自己的密钥，调到的就是他自己的账号。所以封装个人账号类的服务（待办、笔记、网盘）也可以放心给同事用：大家共用连接器，各填各的凭证。
- 谁能在工作流里添加它，看「用户与渠道」页的「可用范围」。新建的连接器默认只有开发者本人，「企业内成员」是「暂未配置」，要手动改成「全部成员」才是全公司可用。点「保存」后还会弹一次「确认保存吗」，不点确认等于没存。（实测）
- 要保护的只有各人自己的那份凭证。凭证不分项目：凭证列表（`GET /webapi/connection_profiles`）和详情接口里都没有项目字段，工作流步骤按凭证 ID 引用它，跨项目复制的副本还指着同一个凭证 ID。（实测，2026-11-12；以前写的「凭证跟着项目走」是按界面猜的，不对）调试台里建的是「测试凭证，仅用于调试」。项目协作者能不能看到凭证的值，未验证。
- 连接器说明或帮助文档里写清楚「密钥去哪拿」，别人照着填就能用。

**例外：公司统一用一把密钥（比如公司的大模型账号）时，可以不开认证，把密钥直接写在操作里。**

- 做法：「要集成的服务」照常选（平台预置里有 DeepSeek 等服务，选它图标和名字都对），「认证与授权」不勾；每个操作的请求头加 `Authorization: Bearer <密钥>`。（实测）
- 效果：调试接口不带凭证也能发出请求，工作流里加这个连接器不用选凭证。没开认证时 `{{baseURL}}` 照样取「基础信息」里的 Base URL。（实测）
- 代价：平台没有连接器级的公共请求头，也没有跨项目共享的凭证（查过官方文档「配置应用凭证」「管理企业集成资源」），所以**每个操作都要单独放一次密钥**，操作越少越好。草稿对象上有个 `actionsBeforeReq` 字段，看名字像连接器级的请求前插件，但界面上没有入口，没试过。
- 风险：能打开连接器开发页的人看得到密钥；调试结果里会带出真正发出去的请求头。工作流运行日志里显不显示请求头，未验证。所以只用专门为集成平台开的、充值有上限的密钥。
- 密钥由用户本人在「操作 → API 配置 → 编辑 → 请求头」里粘贴。AI 生成定义时请求头先放占位文字；以后用接口更新操作，要先 GET 现有对象只改要改的字段，别拿占位文字把粘好的密钥盖掉。

## 7. 凭证、调试、发布（实测）

**凭证。**选「HTTP Bearer Token」这种预置服务时，新建凭证的表单有三格：凭证名称、Base URL、Token。Base URL 每个使用者都要自己填一遍，所以连接器说明里要写清楚填什么。Token 由使用者本人贴。

**调试。**操作页最右边缘有个小箭头，点开才是「调试台」，默认收起。里面依次是「操作 / 凭证 / 入参 / 出参」；先在「凭证」里选或新建凭证，「调试」按钮才亮。

- 在入参框里打完字马上点「调试」，值可能还没被读到，请求会带着空参数发出去。打完字先点一下别处或等一秒。
- 结果页的「HTTP 日志」能看到真正发出去的请求头和请求体，查参数丢没丢看这里。
- 批量试跑不用点界面，直接调上面的 `…/test` 接口。请求体是 `{"inputFormData": "<字符串化的入参>", "authKey": "<凭证的 key>"}`；`authKey` 在界面上点一次调试、从页面请求里抄。入参的写法是每个值包一层类型：

  ```json
  {"project_id": {"type": "string", "value": "inbox"},
   "filter": {"type": "object", "value": {"status": {"type": "array", "value": [{"type": "number", "value": 0}]}}}}
  ```

  返回里 `data.request` 是真正发出去的请求，`data.testResult.testStatus` 是 `Success` 或 `Failure`，`data.output` 是出参。

  一个 58 个操作的连接器，就是这样用脚本串起来全部试跑的：先建一批名字带「测试」的临时数据（分组 → 清单 → 任务 → 评论……），后一步用前一步返回的 ID，最后逐个删掉。两个教训：

  - 写脚本前先看清每个操作的返回长什么样。同一个服务里，有的操作直接返回对象，有的外面多包一层 `result`；取 ID 取错位置，后面一串都会跟着拿到空值，看起来像连接器坏了。
  - 试跑前先确认每种临时数据都删得掉。这次「新建习惯」没有对应的删除接口，留下了一条只能归档、要人手动删的测试数据。

**发布。**「版本与发布」→「发布」分两步：

1. 勾选这次要发布的内容。操作默认一个都没勾，要逐组勾上；勾分组会带上组里全部操作。
2. 填版本号（首次默认 0.1）和描述（必填，200 字内），点「发布」。

已经发布过的连接器再发布，第二步会多一个选择：

- 「在当前版本中发布更新」：编号从 0.1.0 变 0.1.1，已经在用的人自动更新，不用手动切。改提示文字、补必填、配帮助文档这类不影响调用方式的改动用它。平台判断这次没有不兼容变更时会默认选中它。
- 「发布新版本」：版本号前两位递增，使用者要手动切换。

「基础信息」里的帮助文档填一个链接；改了基础信息也要发布一次才对使用者生效。

「用户与渠道」里改可用范围，点「保存」后还会弹一次「确认保存吗」，漏点等于没存。

## 8. 对方用账号密码换令牌：OAuth2 客户端凭证（实测，2026-11-11）

对方接口先用「账号 + 密码」调一个取令牌接口，拿到 `access_token` 后放进 `Authorization` 请求头。这种接口在「认证与授权」里新建认证，类型选「客户端凭证（OAuth2ClientCredentials）」。认证建好后类型就改不了。

**认证要走完五步：基础信息 → 认证表单 → 认证流程 → 测试认证 → 发布认证。**

- **认证表单**里默认有接入账号（`clientID`）和接入密码（`clientSecret`）。可以加一个 `baseURL` 下拉，填正式和测试两个地址。使用者在凭证里选「测试环境」，**所有操作里的 `{{baseURL}}` 就换成测试地址**，「基础信息」里的基础路径只是默认值。（实测：选测试环境的凭证调试，请求都发到了测试域名）
- **认证流程**里，「获取访问令牌」和「刷新访问令牌」各配一个请求。参数用 `{{authInput.clientID}}` 引用表单。令牌取值写在 `computedDataTemplate.fields`：`accessToken` ← `{{getAccessToken.resp.body.access_token}}`，`accessTokenExpiresIn` ← `{{getAccessToken.resp.body.expires_in}}`。令牌放进请求头，要在「添加令牌和加签插件」里写一段 JS：`req.headers['Authorization'] = 'Bearer ' + ctx.authData.accessToken`。
- **测试认证**先建一条「测试数据」，账号密码由使用者本人填。**「获取访问令牌」「刷新访问令牌」两个页签要分别把「认证流程」和「业务接口」各测一遍。**少测一个，发布时会弹「检测到测试风险」。能不能发布，看 `GET /webapi/v2/authentication_drafts/<认证ID>/can_publish`：返回 `auth_draft_not_tested` 就是还有没测的。
- **发布认证**以后，还要回「认证与授权」页点「编辑」，勾上这个认证再保存，连接器才会用它。

**对方网关按请求头放行时，认证流程里的请求要额外加 `Referer`。**实测碰到的网关只放行 `User-Agent` 含 feishu 或 `Referer` 是对方自家域名的请求。

- 取令牌请求只设了 `User-Agent: feishu`，平台发出去照样被网关 403。补上 `Referer` 后就通过了。
- 在本机发同样的请求，只带 `User-Agent` 也能通过。所以推断平台发请求时换掉了自定义的 `User-Agent`（推断）。

遇到这种网关，凡是能加的放行头都加上。

**认证的背后接口。**

| 做什么 | 接口 |
|---|---|
| 读、改认证草稿（整个对象改完 `PUT` 回去） | `GET` / `PUT /webapi/v2/oauth2_client_credentials/authentication_drafts/<认证ID>` |
| 列出测试数据（每条有一个 key） | `GET /webapi/devkit/auth_drafts/<认证ID>/connections` |
| 看上一次认证测试真正发了什么、回了什么 | `GET /webapi/devkit/auth_drafts/<认证ID>/connections/<key>/observed_data` |

`observed_data` 里的 `resp.rawBody` 是 base64。界面上只显示状态码「50 未知错误」时，到这里解出来，就能看到对方真正的返回，比如 nginx 的 403 页面。

**没有另一个环境的账号，也能先确认平台连不连得上那边。**

- 做法：在「测试认证 → 业务接口」里临时加一个指向那个环境的地址，用手头这条测试数据去调。
- 判读：对方回业务的 401（令牌无效），就说明平台的请求过了网关、到了后端；回 nginx 的 403，就是还被拦着。
- 测完删掉这个临时接口，再把两个页签重测一遍。失败的那次测试会让认证变回「未测试」（`auth_draft_not_tested`），以后要重新发布认证时会卡住。

（实测：用测试环境的令牌调正式环境，回 401）

**调试台里的「凭证」下拉看不到认证测试数据**，界面上要再建一张测试凭证。但用接口批量试跑时，可以直接把测试数据的 key 当 `authKey` 传给 `…/actions/<操作ID>/test`，不用再填一遍密码。（实测）

**参数放在查询串或请求头里时**（实测）：

- `formPath` 写 `$.queryParams.<名>` 或 `$.headers.<名>`，模板里照样写 `{{input.<名>}}`，`inputSchema` 是平铺的。
- 查询参数写在 `reqTemplate.queryParams`；请求头写在 `reqTemplate.headers`，比如 `"x-cms-site": "{{input.cmsSite}}"`。
- 没填的参数整个不发。

**用接口试跑时，每个值都要包一层。**写成 `{"current": {"value": 1}}` 就行，`type` 可以不写；写成平铺的 `{"current": 1}` 会报「unmarshal from paramJSON failed」。（实测）

**对方「HTTP 200 + 业务码」的接口，要配状态码。**

- 应用状态码路径填 `{{body.code}}`，成功条件加「应用状态码 等于 0」。
- 配好以后，必填参数漏了这类业务失败会显示「调试失败」，并带出对方的原话，比如「表单id不能为空」。（实测）

「出参」页有「导入 JSON」按钮，看样子是贴一段返回、自动生成字段（界面上看到，这次没用，出参是走接口写的）。

**只给自己用的连接器。**

- 首次发布时，「可用范围」默认只有连接器开发者，「企业内成员」是「暂未配置」。不动它，就只有自己能用。
- 发布渠道默认勾的是「飞书集成平台」，aPaaS 不用勾。（实测）

## 9. 调大模型：平台 AI 额度和自建连接器两条路

- **平台自带的大模型节点**（大模型连接器、AI 条件、意图分支）扣的是「集成平台专属额度」，不能用企业买的飞书 AI 额度。额度要填「飞书集成平台 AI 连接器试用申请表」申请：通过后每月送 400 额度，首次申请每月再加 2000，每次有效 3 个月，一家企业最多申请三次。按次计费，豆包 Doubao-Seed-1.6 系列 0.02 额度一次，DeepSeek-V3 0.2，Deepseek-R1 0.5，Kimi-K2 1。（文档：常见问题「AI 功能额度消耗说明」，2026-11-11 读）
- 自己租户有没有额度，看「设置 → 权益管理 → AI 额度」；能用哪些内置模型、接自定义模型，看「设置 → 模型管理」。没申请过试用的租户显示 0 / 0。（实测）
- **不想走平台额度**：建一个自建连接器直接调模型厂商的接口，用自己的密钥，按厂商的价格付钱，见 §6 的例外做法。（实测：DeepSeek 连接器按这个做法建成，请求能正常发出）
