# 自建连接器

第三方系统没有现成组件，或现成组件动作太少时，自己建。界面每一步、背后的接口、表单定义和认证的写法查 [自建连接器实操](guide/guides/CONNECTOR_DEVKIT.md)。连接器建好后放进工作流、发布流程，看 [搭建与修改工作流](build-and-change.md)。

## 建操作

- 操作多就别在界面里一个个点：在已登录的控制台页面里调 `POST /webapi/v3/connector_drafts/<草稿ID>/actions` 批量建，58 个操作一分钟建完。请求体格式、表单定义写法都在上面那份文档里。（实测）
- 界面按样例生成的入参，会把请求体每个顶层键都变成入参；要写死常量得走接口建。（实测）
- 改一个操作走 `PUT`，要把读到的整个操作对象改完原样发回去；别删了重建，那样会换 ID，已经在用的流程会断。（实测）
- 必填项是字段上的一条校验规则 `formConfig.validations: [{"type": "required"}]`，界面上没有开关。（实测）
- 表单字段的 `formPath` 写错，参数会悄悄丢掉、不报错：它去掉 `$.body.` 后必须等于模板里 `input` 下的路径。建完一定用调试台看一眼「HTTP 日志」里真正发出去的请求体。（实测）
- 查询参数、请求头参数：`formPath` 写 `$.queryParams.名` / `$.headers.名`，模板仍写 `{{input.名}}`。路径参数：地址写 `{{baseURL}}/x/{{input.id}}`，`formPath` 写 `$.path.id`。对方「HTTP 200 + 业务码」的，状态码配 `{{body.code}}` 等于 0，失败时会带出对方原话。（实测）
- 对方直接返回音频、图片这类二进制的，出参类型要选 `file`（`{{ resp | storeFile() }}`）。不这样配，平台会把二进制当文字弄坏。文件入参写 `annotation: ["file"]`，请求体用 `FormData`。某个字段要看另一个入参填没填，写 `{{ input.x != nil ? '常量' : nil }}`。（实测，2026-11-15）
- MCP 服务如果不握手也能直接 `tools/call`，就能一个工具封成一个操作。（对滴答官方 MCP 实测）
- 把大段定义送进页面：页面访问本机 127.0.0.1 会卡死，用「临时 file input + 上传文件工具」。（实测）
- 把本机几十 KB 的定义送进页面：临时 `<input type=file>` 加上传文件工具，本机私有目录里的文件也传得上去；页面里先算 sha256 和本机对上再用。（实测，2026-11-17）

## 认证与密钥

- **连接器是通用工具，密钥是变量**：连接器里不存任何人的密钥，谁用谁在凭证里填自己的，调到的是他自己的账号。所以封装个人账号类的服务也能给同事共用。别把它想成「绑着某人账号、不能给别人用」。要给同事用，在「用户与渠道 → 可用范围」里加人。（实测）
- 密钥一律不写死在操作的请求头里，哪怕全公司共用一把。对方用一把固定密钥的，自建服务配「API Key」认证，默认令牌插件就会加 `Bearer` 头。改完用一条不带凭证的试跑对照，对方回 401，才算确认没有残留。（实测，2026-11-15）
- 第三方接口用固定令牌的，新建时服务选「平台预置」里的 **HTTP Bearer Token**，不用写认证插件。（实测）
- 对方要先用账号密码换令牌：认证选「客户端凭证（OAuth2ClientCredentials）」，认证表单加一个 `baseURL` 下拉放正式、测试两个地址，使用者选哪个，所有操作的 `{{baseURL}}` 就跟着换。测试认证时「获取」「刷新」两个页签都要把「认证流程」和「业务接口」各测一遍，否则发布时报「测试风险」；发布后还要回「认证与授权」勾上它。（实测）
- 同一个对方系统再建连接器：「要集成的服务」选同一个自建服务，「认证与授权」勾上已经发布的那个认证。使用者的老凭证直接能用，不用重填账号密码。（实测，2026-11-14）
- 同一个服务加了第二种认证，它的插件也要带上对方网关要的放行头（照第一种认证抄），不然会出现正式环境通、测试环境 403。（实测，2026-11-16）
- 同一个对方系统，前台、后台要不同的身份时（比如前台用接入账号换令牌，后台用管理员的固定令牌）：一个连接器勾两种认证，在每个后台操作的「基本信息 → 操作支持的认证方式」里只留后台那种（字段 `supportedAuthTypes: ["api_key"]`），前台留空两种都能用。别为此拆成两个连接器。（实测，2026-11-16）
- 对方发来的令牌常连着 `Bearer ` 和密码一起发。API Key 认证的插件先去掉 `Bearer ` 前缀再加，带不带都能用；使用的人把密码当令牌贴进去时，对方 401 会原样回显，看试跑结果只看 `code`、`msg`。（实测，2026-11-16）
- 对方网关按 `User-Agent` 放行时，平台发出的请求会被拦（推断它换掉了自定义 UA），再加一个对方认可的 `Referer` 才过。认证测试只显示「50 未知错误」时，读 `…/connections/<key>/observed_data` 看真实返回。（实测）

## 先摸清对方系统

- 令牌取得到，不代表每个接口都有权限：对方可能按接入账号分接口权限，后台接口回「授权失败」。批量建之前先拿真实令牌把每类接口各调一个。对方文档的成功码、错误状态、必填项也常和实际不符，状态码和出参以真实返回为准。（实测，2026-11-14）
- 对方文档的枚举值和时间格式也常和真实数据不一样（实测碰到过：语言是 `ZH`/`EN`，文档写 `zh_CN`/`en_US`；时间是 `2026-06-15 09:00:00`，文档写 ISO 格式）。写错时，新增只回「服务器内部异常」，查询则静悄悄查不到。所以建新增、修改操作前，先用「查详情」读一条已有记录，照它的字段格式来。（实测，2026-11-16）
- 修改接口没传的字段是保留还是清空，要每个接口单独试：先只传 ID 和一个字段，再查详情比前后。同一个系统里也会不一样，实测有的接口全保留，有的会把没传的关联（比如嘉宾列表、所属分组）清空。试出来写进操作说明。（实测，2026-11-16）

## 试跑

- 批量试跑调 `…/actions/<操作ID>/test`，不用一个个点调试台。（实测）
- 试跑接口的入参每个值都要包一层，写成 `{"名": {"value": 值}}` 就行，平铺写会报 `unmarshal from paramJSON failed`；认证测试数据的 key 可以直接当 `authKey`。（实测）数组和对象里面每一层也要包，不包的话那一项会悄悄变成 `null` 发出去。（实测，2026-11-16）
- 核对出参定义：试跑返回的 `output` 就是整个 body，不按定义过滤，要拿 `response.objectBody` 和操作的 `outputSchema` 比。（实测，2026-11-16）

## 发布与下线

- 发布后的小改动、补发新操作，都选「在当前版本中发布更新」，算兼容变更，使用者自动生效，在用的流程不用动。（实测；补发新操作 2026-11-16 实测）
- 发布连接器更新时，新加的操作默认没勾，要在第一步手动勾上，右边「新增」的数目对上再下一步。「发布」这一下可能被 Claude Code 的自动安全检查拦下，拦了就留给用户自己点，别绕。（实测，2026-11-17）
- 发布时可以只勾试跑通过的分组或操作，没勾的留在草稿、不进版本。首次发布的第二步就能把「可用范围」设成全部成员。发布后用 `GET /webapi/market/connector_preview/<版本ID>`（带 `x-csrf-token`）核对版本里到底有哪些操作。（实测，2026-11-14）
- 发布过的自建连接器删不掉，「删除连接器」只对从没发布过的连接器开放。老连接器要下线，先扫全租户确认没人用，再在「版本与发布」里对每个版本点「停止支持」：新流程不能再用这个版本，已经在用的流程不受影响，界面上没有恢复按钮。所以试验用的连接器别急着发布。细节见 [自建连接器实操](guide/guides/CONNECTOR_DEVKIT.md#7-凭证调试发布实测)。（实测，2026-11-15）

## 把流程换到新连接器

- 找「谁在用某个连接器」：全租户扫草稿和线上版本，按节点的 `connectorId` 比；不知道老版本 ID 时，按节点 ID 前缀（就是连接器 key）或参数里的关键字搜。2026-11 扫 264 条用了约 4 分钟。（实测）
- 流程从老连接器换到新连接器，先证明新的不比老的差，再动流程：用 `search_node_log` 拿老节点最近真实跑过的入参，原样喂给新连接器的试跑接口；下游有脚本的，把新返回交给同一段脚本再算一遍，和老运行的结果逐条比。一条打标签流程这样比了 9 次，挑出的任务、标签、跳过的任务全都一样。（实测，2026-11-15）
- 换节点只改 `operation`（已发布版本 ID 和版本里的操作 ID）、凭证、节点 ID，下游引用和 `structure` 跟着改，参数原样不动。写草稿前存一份旧的，写完逐个节点比，只该有这几处不同。用户在凭证里贴好密钥后，拿凭证 ID 当 `authKey` 试跑一个只读操作，确认密钥能用再发布。查 ID 的接口见 [自建连接器实操](guide/guides/CONNECTOR_DEVKIT.md#7-凭证调试发布实测)。（实测，2026-11-15）

## 拿飞书 token：用自建连接器

HTTP 节点的凭证只支持 Basic、API Key、Bearer，换不了飞书 token。项目变量没有加密类型。所以别在流程里写 `app_secret`。（实测）

做法：建一个自建连接器，认证选「飞书应用身份认证」，平台会自己注入 `tenant_access_token`。（实测）

- Base URL 填 `https://open.feishu.cn/open-apis`。URL 里写 `{参数}` 占位，会自动变成输入项。
- 每个操作必须选「所属分组」。
- 发布后只对开发者自己可见。渠道只有「飞书集成平台」和「飞书 aPaaS」，多维表格自动化的步骤菜单里用不了它。
- 飞书原生连接器不支持「关联组织」接口。要调关联组织的接口，只能走自建连接器。（实测，174 个连接器逐个看过）
- 包飞书接口的自建连接器也要配状态码：飞书有的错误是 HTTP 200 加业务码。关联组织接口里，ID 不存在回 HTTP 200、`code 40001`，只按 HTTP 状态判成败的话试跑和流程里都显示成功。应用状态码路径填 `{{body.code}}`、错误描述填 `{{body.msg}}`，成功条件加「应用状态码 等于 0」。（实测，2026-11-17）
- 关联组织接口的实际返回和飞书那份说明文档不一样：成员和部门列表在 `data.collaboration_entity_list`（文档写 `item_list`），成员详情是 `name`、`open_id`、`union_id`（文档写 `user_name`、`open_user_id`、`union_user_id`）。出参照真实返回定义。没有「取全部成员」，要从根部门 `0` 逐层往下取；成员详情一次一个。（实测，2026-11-17）
